## 核心代码详解（约 300 行关键实现）

本节按“接口请求—数据持久化—文本向量化—聚类分析—趋势聚合—前端反馈”的真实顺序解读项目。内容以 app.py、src/storage.py、src/analysis.py、src/hybrid_service.py 与 prototype.html 为依据，展示 TF-IDF、K-Means、趋势过滤和错误响应如何协同工作。

### 1. 接口入口、参数边界与错误响应

后端使用 Python 标准库 HTTP 服务，所有接口都返回 JSON。先对分页参数做类型和范围约束，再进入业务层；分析过程发生异常时返回固定结构，避免前端因收到非 JSON 内容而二次报错。

~~~python
def parse_limit(value, default=50, maximum=100):
    try:
        limit = int(value or default)
    except (TypeError, ValueError):
        limit = default
    return max(1, min(limit, maximum))


def _send_json(handler, payload, status=200):
    body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
    handler.send_response(status)
    handler.send_header("Content-Type", "application/json; charset=utf-8")
    handler.send_header("Content-Length", str(len(body)))
    handler.end_headers()
    handler.wfile.write(body)


def _error(handler, status, message, detail=None):
    payload = {"error": message}
    if detail:
        payload["detail"] = detail
    _send_json(handler, payload, status)


def do_get(self):
    try:
        if self.path.startswith("/api/analytics/summary"):
            return _send_json(self, store.analysis_summary())
        if self.path.startswith("/api/analytics/keywords"):
            return _send_json(self, store.keyword_stats())
        if self.path.startswith("/api/analytics/trends"):
            return _send_json(self, store.trend_stats())
        return _error(self, 404, "not found")
    except Exception as exc:
        logger.exception("analytics request failed")
        return _error(self, 500, "analysis unavailable", str(exc))
~~~

`parse_limit` 使用默认 50、最大 100，避免负数、文本或超大数字造成查询压力。`_send_json` 集中处理 UTF-8 编码、响应头和内容长度。分析接口的 500 响应会带回 `analysis unavailable` 与 `detail`，因此页面可以区分服务异常和没有数据。

~~~python
def is_valid_import_token(headers):
    expected = os.environ.get("VISIONPULSE_IMPORT_TOKEN", "")
    supplied = headers.get("X-Import-Token", "")
    return bool(expected) and hmac.compare_digest(supplied, expected)


def require_import_token(handler):
    if not is_valid_import_token(handler.headers):
        _error(handler, 401, "invalid import token")
        return False
    return True
~~~

批量导入、更新、删除和清理操作由环境变量令牌保护，`hmac.compare_digest` 采用常量时间比较，降低简单时序攻击风险。

### 2. SQLite 事务、去重与自动刷新

论文主表保存题目、摘要、关键词、会议、年份、原文链接和来源类型；分析结果分别写入元信息、关键词统计、趋势统计与论文—关键词关联表。导入使用批量事务和唯一键冲突更新，事务成功后才刷新分析结果。

~~~python
def upsert_many(self, papers):
    rows = [self._normalize_paper(paper) for paper in papers]
    with self.connection:
        self.connection.executemany(
            """
            INSERT INTO papers
              (dblp_key, title, abstract, keywords, venue, year,
               authors, url, paper_type)
            VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)
            ON CONFLICT(dblp_key) DO UPDATE SET
              title=excluded.title,
              abstract=excluded.abstract,
              keywords=excluded.keywords,
              venue=excluded.venue,
              year=excluded.year,
              authors=excluded.authors,
              url=excluded.url,
              paper_type=excluded.paper_type
            """, rows)
    self.refresh_analysis()


def refresh_analysis(self):
    from .analysis import AnalysisEngine
    AnalysisEngine(self.connection).refresh()
~~~

事务提交成功后才调用刷新函数；如果批量导入中途失败，SQLite 会整体回滚，避免主数据与统计数据不一致。`ON CONFLICT(dblp_key)` 把论文唯一标识作为去重依据，远端搜索回写也不会重复扩大趋势分母。

### 3. 本地优先的混合检索

搜索先查询 SQLite，本地记录不足时再请求 DBLP 等公开接口；远端失败仅影响补充结果，不阻断本地结果返回。远端成功数据规范化、去重后回写，随后触发分析刷新。

~~~python
def search(self, query, venue=None, year=None, limit=20):
    local = self.store.search_papers(
        query, venue=venue, year=year, limit=limit
    )
    if len(local) >= limit:
        return local[:limit]

    try:
        remote = self._search_dblp(
            query, venue=venue, year=year,
            limit=limit - len(local)
        )
    except Exception:
        logger.warning("remote search failed", exc_info=True)
        remote = []

    merged = self._merge_by_key(local, remote)
    if remote:
        self.store.upsert_many(remote)
    return merged[:limit]
~~~

这种设计形成“搜索—补充—保存—重新分析”的闭环。合并时保持本地结果顺序，远端返回顺序不会打断用户当前的阅读位置。

### 4. TF-IDF：把论文文本转为可计算向量

分析引擎将题目、摘要和关键词融合为一份文本，先小写化、正则分词、剔除通用词，再以 1-gram 和 2-gram 构建 TF-IDF 稀疏矩阵。词表最多保留 4000 项，兼顾区分能力与轻量部署成本。

~~~python
GENERIC_TERMS = {
    "computer", "science", "artificial", "intelligence",
    "method", "methods", "approach", "system", "using",
}


def _document(self, paper):
    parts = [paper.get("title", ""), paper.get("abstract", ""),
             paper.get("keywords", "")]
    text = " ".join(parts).lower()
    tokens = re.findall(r"[a-z][a-z0-9-]{2,}", text)
    tokens = [token for token in tokens if token not in GENERIC_TERMS]
    return " ".join(tokens)


def _vectorize(self, papers):
    documents = [self._document(paper) for paper in papers]
    vectorizer = TfidfVectorizer(
        lowercase=True,
        stop_words=sorted(GENERIC_TERMS),
        ngram_range=(1, 2),
        max_features=4000,
        token_pattern=r"(?u)\\b[a-zA-Z][a-zA-Z0-9-]{2,}\\b",
    )
    matrix = vectorizer.fit_transform(documents)
    return matrix, vectorizer
~~~

TF 表示词在当前论文中的出现强度；IDF 则降低在大量论文中普遍出现的词的权重。两者相乘后，`segmentation`、`diffusion model` 等区分度更高的术语会被突出。二元短语还能识别 `foundation model`、`visual-language` 等复合概念。空数据集或无有效文本时，分析引擎写入零值元数据并安全返回，不在空矩阵上调用聚类。

### 5. K-Means：从向量空间识别研究方向

聚类数并未固定：只有一篇论文时使用 1 类，规模变大后按论文数平方根估算，并限制在 2—10 类。固定随机种子和多次初始化让同一数据快照的结果可复现。

~~~python
def _cluster_count(self, size):
    if size <= 1:
        return 1
    return min(10, max(2, round(math.sqrt(size))))


def _cluster(self, matrix, papers):
    count = self._cluster_count(len(papers))
    if count == 1:
        labels = [0] * len(papers)
        centers = None
    else:
        model = KMeans(
            n_clusters=count,
            random_state=42,
            n_init=10,
        )
        labels = model.fit_predict(matrix)
        centers = model.cluster_centers_
    return labels, centers


def _top_terms(self, centers, feature_names, top_n=8):
    if centers is None:
        return []
    result = []
    for center in centers:
        order = center.argsort()[::-1][:top_n]
        result.append([feature_names[index] for index in order])
    return result
~~~

K-Means 依据向量距离把相似论文归入同一簇，簇中心代表该簇的核心特征。平台从中心向量中提取高权重词作为方向解释标签。聚类标签表示文本相似集合，而非人工预定义的学科类别，因此页面支持由关键词反查论文，保证结论可追溯。

### 6. 关键词关联与趋势过滤

每次刷新先清理旧派生结果，再写入当前快照。关键词统计保留前 80 项；趋势只计入 CVPR、ICCV、ECCV、年份有效且不是 `user-import` 的标准论文记录。

~~~python
def _write_keywords(self, cursor, papers, vectorizer, matrix):
    scores = matrix.sum(axis=0).A1
    names = vectorizer.get_feature_names_out()
    order = scores.argsort()[::-1][:80]
    for rank, index in enumerate(order, start=1):
        keyword = names[index]
        cursor.execute(
            "INSERT INTO keyword_stats(keyword, score, rank) "
            "VALUES (?, ?, ?)",
            (keyword, float(scores[index]), rank),
        )
        for paper_index, row in enumerate(matrix[:, index].toarray()):
            if row[0] > 0:
                cursor.execute(
                    "INSERT INTO keyword_papers(keyword, dblp_key) "
                    "VALUES (?, ?)",
                    (keyword, papers[paper_index]["dblp_key"]),
                )


def _write_trends(self, cursor, papers):
    allowed = {"CVPR", "ICCV", "ECCV"}
    counts = Counter()
    for paper in papers:
        venue = str(paper.get("venue", "")).upper()
        year = paper.get("year")
        if venue not in allowed or not isinstance(year, int):
            continue
        if paper.get("paper_type") == "user-import":
            continue
        for keyword in self._keywords_for(paper):
            counts[(keyword, venue, year)] += 1
    for (keyword, venue, year), count in counts.items():
        cursor.execute(
            "INSERT INTO trend_stats(keyword, venue, year, paper_count) "
            "VALUES (?, ?, ?, ?)",
            (keyword, venue, year, count),
        )
~~~

趋势过滤的业务含义是“只比较拥有统一统计口径的顶会正式论文”：非三大会议、缺失年份记录和手工导入的临时记录不会进入年度曲线。年度热词变化反映的是当前标准化快照，而不是混杂的任意输入。

### 7. 前端加载、有限重试与失败可见性

前端使用原生 JavaScript，通过统一 `getJSON` 检查 HTTP 状态。首页分析数据第一次加载失败时最多重试两次；仍失败则展示明确提示，不把空图表误导为“没有趋势”。

~~~javascript
async function getJSON(path) {
  const response = await fetch(API_BASE + path, {
    headers: { Accept: "application/json" },
  });
  if (!response.ok) {
    throw new Error("HTTP " + response.status);
  }
  return response.json();
}

let analyticsRetries = 0;

async function hydrateAnalytics() {
  try {
    liveAnalytics = await getJSON("/api/analytics/summary");
    liveTrendData = await getJSON("/api/analytics/trends");
    renderDashboard(liveAnalytics, liveTrendData);
    setLiveStatus("实时分析已连接");
  } catch (error) {
    console.error("analysis hydration failed", error);
    if (analyticsRetries < 2) {
      analyticsRetries += 1;
      setLiveStatus(
        "分析服务连接重试中（" + analyticsRetries + "/2）"
      );
      window.setTimeout(hydrateAnalytics, 1800);
    } else {
      setLiveStatus("分析服务暂时不可用，请稍后刷新", true);
    }
  }
}
~~~

因此，前端提示“分析失败”通常意味着分析接口返回 500、派生表尚未刷新、数据库文件不可读，或部署环境 API 地址不一致。前端保留错误与重试状态，后端记录异常细节，两层信息可共同用于排查。
